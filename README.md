# پارس‌تی‌وی

فرم چندمرحله‌ای فارسی برای تجمیع نیاز مشتری یک فروشگاه تلویزیون، همراه با حساب کاربری، ذخیره پیش‌نویس، قفل بعد از ثبت نهایی، چت‌بات کمپین و پنل مدیریت.

## چرا این فیلدها؟

با بررسی مسیر خرید تلویزیون در فروشگاه‌هایی مثل دیجی‌کالا، تکنولایف، سامسونگ و بست‌بای این نیازها تکرار می‌شود:

- انتخاب سایز صفحه (۳۲ تا ۸۵ اینچ) که قیمت را عوض می‌کند
- برند، نوع پنل، رزولوشن، سیستم‌عامل و گیمینگ
- نصب دیواری / پایه، براکت و جمع‌آوری تلویزیون قبلی
- هزینه ارسال، کاور محافظ و بیمه حمل **قبل از ورود به درگاه پرداخت**
- شماره موبایل برای کمپین و پیگیری ارسال

## اجرا

```bash
cp .env.example .env
npm install
npm run setup
npm run dev
```

سایت روی `http://localhost:3000` باز می‌شود.

### حساب مدیر

- ایمیل: `admin@parstv.ir`
- رمز: `Admin1234!`

مشتری با ایمیل و رمز ثبت‌نام می‌کند (بدون تأیید ایمیل)، فرم را مرحله‌به‌مرحله پر می‌کند و پیش‌نویس ذخیره می‌شود. بعد از «ثبت نهایی و ورود به درگاه» دیگر نمی‌تواند فرم را دوباره ویرایش کند.

## اجرا با داکر

```bash
docker build -t parstv .
docker run -p 3000:3000 \
  -e AUTH_SECRET="یک رشته تصادفی و طولانی" \
  -v parstv-data:/app/data \
  parstv
```

یا با داکر کامپوز:

```bash
AUTH_SECRET="یک رشته تصادفی و طولانی" docker compose up --build
```

کانتینر در هر بار اجرا اسکیمای دیتابیس را همگام می‌کند و حساب مدیر را می‌سازد، پس بعد از بالا آمدن، همان ایمیل و رمز بالا کار می‌کند.

دیتابیس SQLite در `/app/data/parstv.db` ساخته می‌شود؛ برای این‌که با حذف کانتینر پاک نشود باید یک والیوم روی `/app/data` وصل باشد.

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `AUTH_SECRET` | – | کلید امضای کوکی نشست؛ در محیط واقعی حتماً مقدار بدهید |
| `DATABASE_URL` | `file:/app/data/parstv.db` | مسیر فایل SQLite |
| `PORT` | `3000` | پورتی که سرور روی آن گوش می‌دهد |
| `DB_PUSH_ON_START` | `true` | همگام‌سازی اسکیما هنگام اجرا |
| `SEED_ON_START` | `true` | ساختن/به‌روزرسانی حساب مدیر هنگام اجرا |
