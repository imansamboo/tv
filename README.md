# دُکون بازار

فرم چندمرحله‌ای فارسی برای جمع‌آوری **نیازمندی‌های صاحب فروشگاه تلویزیون** — نه اطلاعات خرید مشتری. صاحب فروشگاه می‌گوید سایت فروش تلویزیون چه امکاناتی باید داشته باشد: کاتالوگ، تجربه خرید، پرداخت، ارسال و پنل مدیریت.

## چه چیزی جمع می‌شود؟

- معرفی فروشگاه و وضعیت سایت فعلی
- برندها و بازه سایزهای کاتالوگ
- امکانات سایت برای مشتری نهایی (فیلتر، مقایسه، پیکربندی مرحله‌ای، چت و ...)
- درگاه پرداخت، ارسال، نصب و گارانتی
- ابزارهای پنل مدیریت برای خود فروشگاه
- سبک طراحی و سایت‌های مرجع

**شماره موبایل مشتری یا جزئیات خرید تلویزیون گرفته نمی‌شود.**

## بیزینس‌ها و فرم نیازمندی هر بیزینس

هر کاربر هنگام ثبت‌نام از یک لیست کشویی بیزینس خودش را انتخاب می‌کند (`User.businessId`) و بعد
از ثبت‌نام فرم نیازمندی همان بیزینس برایش باز می‌شود. مدیر در `/admin/businesses` بیزینس می‌سازد
(خالی یا کپی از یک بیزینس دیگر) و فرم آن را می‌سازد: مرحله‌ها، فیلدها و گزینه‌ها را اضافه، ویرایش،
جابه‌جا یا حذف می‌کند و در تب «پیش‌نمایش» فرم را همان‌طور که کاربر می‌بیند امتحان می‌کند. همه
حالت‌های فرم قبلی پشتیبانی می‌شود: متن کوتاه، متن بلند، لیست کشویی، دکمه‌های تک‌انتخابی،
دکمه‌های چندانتخابی (مولتی سلکت)، گزینه «سایر» با کادر توضیح، فیلد اجباری، حداقل طول، پیام خطای
دلخواه، گزینه پیش‌فرض، راهنما و متن نمونه.

فرم کامل قبلی به‌صورت سید با نام بیزینس **«کالای دیجیتال - تلویزیون»** وارد می‌شود
(`lib/business-seed.ts`). اجرای سید کاربران قبلی را به همین بیزینس منتقل و پاسخ‌های قدیمی‌شان را
به ساختار جدید تبدیل می‌کند. هنگام ثبت نهایی یک کپی از فرم کنار پاسخ‌ها ذخیره می‌شود، بنابراین
تغییرات بعدی فرم فقط روی پیش‌نویس‌ها اثر دارد. بیزینسی که کاربر دارد حذف نمی‌شود؛ به‌جای آن
می‌توان آن را غیرفعال کرد تا در ثبت‌نام نمایش داده نشود.

### تولید فرم با Cursor API

در `/admin/businesses` دکمه **«تولید فرم با هوش مصنوعی»** نوع کسب‌وکار را (مثلاً «فروشگاه آنلاین
داروخانه») به Cursor Cloud Agents API می‌فرستد و یک فرم نیازمندی کامل می‌سازد. کسب‌وکار جدید
**غیرفعال** ذخیره می‌شود تا در فرم‌ساز بازبینی و منتشر شود.

کلید API را در `.env` تنظیم کنید:

```bash
CURSOR_API_KEY="your-cursor-api-key"
```

کلید را از Cursor Dashboard → API Keys بگیرید. این کلید فقط سمت سرور استفاده می‌شود. پرامپت‌ها
در `prompts/cursor-requirement-form-generator.md` و `lib/form-generation-prompt.ts` نگه‌داری
می‌شوند. فرم‌های تولیدشده برای سازگاری با قیمت‌گذاری خودکار، کلیدهای مشترک (مثل
`paymentGateways` و `designStyle`) را با فرم تلویزیون هماهنگ نگه می‌دارند.

## فرم قیمت‌گذاری

بعد از ثبت نهایی فرم نیازمندی‌ها، کاربر پیام «فرم قیمت‌گذاری شما در حال آماده‌سازی است و به‌محض
آماده شدن نمایش داده می‌شود» را می‌بیند و برای مدیر یک اعلان ثبت می‌شود (`/admin/notifications`).
مدیر در `/admin/pricing-forms` یک فرم اختصاصی می‌سازد. هر فرم بخش‌ها و موردهای مستقل خودش را
دارد (عنوان، قیمت، تصویر و توضیح) که مثل قبل قابل افزودن، ویرایش، حذف، فعال/غیرفعال کردن و
جابه‌جایی است. فرم جدید از روی «قالب پیش‌فرض» (`/admin/pricing`)، از روی یک فرم دیگر یا خالی ساخته
می‌شود و تغییر آن روی قالب یا فرم‌های دیگر اثری ندارد. در پایان مدیر فرم را به کاربر اختصاص
می‌دهد (از صفحه ویرایش فرم یا از صفحه جزئیات نیازمندی‌های کاربر). از این لحظه کاربر در
`/pricing` همان فرم را می‌بیند و پس از ثبت، اعلان دیگری برای مدیر ثبت می‌شود. یک «مورد پایه» همیشه انتخاب‌شده است و قیمت آن نقطه شروع محاسبه است؛ هر
امکان اختیاری که تیک بخورد قیمتش به مجموع اضافه می‌شود و مجموع بلافاصله در سمت کاربر به‌روز
می‌شود.

قیمت نهایی همیشه در سرور و از قیمت‌های ذخیره‌شده در دیتابیس محاسبه می‌شود؛ مبلغی که مرورگر
می‌فرستد نادیده گرفته می‌شود. هنگام ثبت، از همه موردهای همان لحظه (عنوان، توضیح، قیمت و بخش)
یک کپی ذخیره می‌شود، بنابراین تغییر بعدی قیمت‌ها یا حذف یک مورد، قیمت فرم‌های ثبت‌شده را
تغییر نمی‌دهد.

بخش‌ها و موردهای هر فرم (و قالب پیش‌فرض) در پنل مدیریت تنظیم می‌شوند: ساخت، ویرایش، حذف،
فعال/غیرفعال کردن، جابه‌جایی ترتیب، تعیین نوع «پایه» یا «اختیاری» و بارگذاری یا حذف تصویر.
فرم‌های ثبت‌شده کاربران در `/admin/quotes` قابل مشاهده است.

تصویر هر مورد اختیاری است. فایل‌های بارگذاری‌شده در `public/uploads/pricing` ذخیره می‌شوند
(این مسیر در `.gitignore` است و در اجرای اول ساخته می‌شود). اندازه پیشنهادی تصویر مربعی و
حداقل ۴۰۰×۴۰۰ پیکسل است و در کارت‌ها به‌صورت مربع ۱۱۲ پیکسلی نمایش داده می‌شود. اگر موردی
تصویر نداشته باشد هیچ کادر خالی نمایش داده نمی‌شود.

## اجرا

```bash
cp .env.example .env
npm install
npm run setup
npm run dev
```

سایت روی `http://localhost:3000` باز می‌شود.

### حساب مدیر

- ایمیل: `admin@fariman.ir`
- رمز: `Admin1234!`

صاحب فروشگاه با ایمیل و رمز ثبت‌نام می‌کند (بدون تأیید ایمیل)، فرم را مرحله‌به‌مرحله پر می‌کند و پیش‌نویس ذخیره می‌شود. بعد از «ثبت نهایی» دیگر نمی‌تواند فرم را دوباره ویرایش کند و به فرم قیمت‌گذاری هدایت می‌شود.

`npm run setup` شِمای دیتابیس را با `prisma db push` می‌سازد و داده اولیه فرم قیمت‌گذاری و
بیزینس «کالای دیجیتال - تلویزیون» را هم اضافه می‌کند. برای اعمال جدول‌های جدید روی یک دیتابیس موجود همین دستور کافی است.
